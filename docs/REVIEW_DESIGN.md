# 复习系统设计

## 一、我们的独特优势

多邻国的错题来自**它给你出的题**。我们的错题来自**你自己想说的话**。

这两者不是同一件事：

| | 多邻国 | 译键 |
|---|---|---|
| 错题来源 | 系统出的练习题 | 你真实输入过的句子 |
| 错了意味着 | 没掌握这个知识点 | 你想表达这个意思，但没说对 |
| 错题归属 | 题库里的一道题 | 你自己的表达 |
| 用户感受 | "我又错了" | "我当时是这么想的" |

最后一行是关键。复习一句自己写过的错句，和复习一道系统出的题，心理负担完全不同——前者是**回顾自己的成长**，后者是**被检查**。

所以我们的复习系统的核心不是"练题"，而是：**把你曾经说不清楚的话，变成说得清楚的话**。

## 二、这个优势要求什么

如果认下这个定位，有几件事就必须做到，否则优势只是口号。

### 1. 错题必须保留"当时的样子"

只存 `wrong → right` 不够。要保留：

- 你当时的完整原句
- 上下文（你在跟谁说话、在什么场景）
- 当时 AI 给你的解释
- 你当时是不是接受了这个纠正（还是继续用了错的）

最后一条尤其重要：**如果你当时没接受、之后又错了一次，这个点就是真正的顽疾**，应该加权。

### 2. 错题必须按"表达意图"组织，不是按句子

同一件事你可能会说错好几次，每次句子都不同：

```
第一次：I very like this movie.
第二次：I very like the film.
第三次：I really very like it.
```

按句子存，这是三道错题。按知识点存，这是**一个问题：very 不能修饰动词**。

所以错题的组织单位是**错误点（mistake point）**，包含：
- 类型（拼写 / 语法 / 用词 / 表达）
- 你说的形式 vs 正确形式
- 归属的知识点（用 AI 归类，比如"very 修饰动词"）
- 犯过几次、最近一次是什么时候、连续答对几次

### 3. 必须能看到"改进"

这是你说的第二半：**跟踪改进情况**。

不是显示"你练了 31 张"，而是：

```
very 修饰动词
  错过 5 次 → 最近 3 次都对
  ████████░░  快要掌握了

缺少冠词
  错过 12 次 → 最近 1 次对
  ██░░░░░░░░  还在反复
```

关键在**"最近 N 次"**而不是"总共对了多少"。因为真正的改进是**最近不再犯**，不是历史平均。

这需要一个滑动窗口：记录每个错误点最近 10 次的作答结果，看其中的正确率趋势。

### 4. 复习必须能回到写作现场

这是我们比多邻国强的地方，但现在的实现完全没利用：

- 复习发生在 App 里
- 写作发生在输入法里
- 两者不通信

应该做到：**你在输入法里再次犯同一个错时，面板里多一行"这个点你上半年错过 5 次，这次对了"**。这才是把复习和真实使用连起来。

## 三、系统设计

### 3.1 数据结构

```
MistakePoint              一个错误点
├─ id                     知识点标识（如 "very-modifies-verb"）
├─ kind                   拼写 / 语法 / 用词 / 表达
├─ wrongForms[]           你犯过的具体错误形式（去重）
├─ correctForm            正确形式
├─ explanation            AI 给的解释（合并最早的与最新的）
├─ occurrences            总犯错次数
├─ history[]              最近 N 次的作答结果（true/false + 时间戳）
├─ correctStreak          当前连续答对
├─ bestStreak             历史最长连对
└─ lastSeen               最后一次遇到的时间

MistakeInstance           一次具体的犯错（指向 MistakePoint）
├─ pointId
├─ sourceSentence         你当时写的完整句子
├─ sourceTranslation      你想表达的中文
├─ context                上下文
├─ timestamp
└─ accepted               你当时是否接受了纠正
```

关键点：
- **Point 是长期的，Instance 是历史的**
- Point 决定"要复习什么"，Instance 决定"用什么句子复习"
- 复习时优先用**你最近一次犯这个错的句子**——那是你最熟悉的上下文

### 3.2 调度

不用 HLR（需要海量数据训练），用**改进版 Leitner + 滑动窗口**：

```
每个错误点有 stage 0..4
间隔：1 / 3 / 7 / 16 / 35 天（比现在的 1/3/7/15/30 更接近 FSRS 的曲线）

答对：stage + 1
答错：stage 归 0，但**不重置 history**（历史保留，用于判断是否真的顽疾）
模糊：stage 不变，间隔减半

额外规则：
- 如果 history 最近 10 次正确率 ≥ 90%，直接跳到 stage 4（不必慢慢爬）
- 如果某个点连续错了 3 次以上，标记为「顽疾」，降低单次间隔、提高出现频率
```

**为什么不用固定间隔表**：因为我们的错误点是**语义级**的，不是词条。"very 修饰动词"这个点比"recieve 拼写"要难得多，应该有不同的间隔曲线。用 stage 自适应而不是查表。

### 3.3 三种会话

| 会话类型 | 组成 | 长度 |
|---|---|---|
| **今日复习** | 到期的错误点，按 stage 从低到高 | 10-14 题 |
| **错题重练** | 最近的 MistakeInstance，按句子重现 | 最多 10 题 |
| **生成新句** | AI 按薄弱点造题 | 5 题 |

**今日复习的会话结构**（借鉴多邻国验证过的做法）：
```
开场：3 题热身（答对率高的点，建立信心）
主体：6-8 题（到期的点，混合题型）
挑战：1-2 题（stage 最高的点，用最难题型：RECALL 或 FIX_ERROR）
收尾：本次答错的点，集中重做（错了回队尾，直到答对）
```

收尾是核心——多邻国验证过这个做法有效，我们照做。

### 3.4 结束页

不做"完成！🎉",做**今天的变化**：

```
今天复习了 12 个错误点

巩固了        7 个（连续答对 ≥ 2）
还需要练      3 个（这次又错了）
新掌握        2 个（连续答对 ≥ 5，进入长间隔）

最需要关注的
  very 修饰动词
    错过 5 次 · 最近 3 次全对 · 下次 7 天后
```

### 3.5 写作时的提醒（机会）

在输入法翻译面板里，如果 AI 检测到用户当前句子的错误**匹配已知的 MistakePoint**，在纠正条目上加一行：

```
✎ very 不能直接修饰动词
   用 really / very much
   ⤷ 你错过 5 次，这半年第一次改对
```

这不是打扰，是**把复习的成果立刻用上**。而且它只在你真的犯错时出现，不主动弹出。

## 四、实现顺序

| 阶段 | 内容 | 依赖 |
|---|---|---|
| 1 | MistakePoint 数据层 + 从现有 corrections 归类 | 现有 practice.jsonl |
| 2 | 改进调度（滑动窗口 + 自适应 stage） | 1 |
| 3 | 会话结构（三段 + 收尾重练） | 2 |
| 4 | 结束页（变化而非数字） | 3 |
| 5 | 输入法里的错点提醒 | 1 |

前四个是复习系统本身，第五个是把优势真正用起来。第五个可以晚一点，但**它是整个设计的落点**。

## 五、不做的事

- **不做 XP、联赛、连击惩罚**——多邻国的排行榜直接奖励刷简单题，是明确的反学习机制
- **不做"HRL 式"预测模型**——需要百万级数据，我们只有自己的几百条
- **不做"技能碎裂"**——内容量不够，会显得全碎
- **不把错题当练习题存**——那是多邻国的做法，也是它被抱怨的地方
