# 译键吉祥物：信鸽「咕咕」设计规范

## 一、为什么是信鸽

译键做的事只有一件：**在两个语言之间传递一段意思**。

信鸽是人类用了几千年的同一个动作——把消息从这一头送到那一头，中间隔着距离、语言、文化。它比猫头鹰（智慧）更准确地对应「翻译」这个动作本身，而不是这件事需要的能力。

名字取「咕咕」：鸽子的叫声，也是中文里一个柔软、没架子的音节，符合一个从不居高临下纠正你的老师形象。

## 二、造型原则

三条硬约束，按优先级：

1. **48dp 下仍然认得出**
   主体必须是一个连续的、可一眼命名的形状。删掉所有只有在大图上才看得见的东西。
2. **两三个形状构成**
   头 + 身体溶成一个圆润的水滴；翅膀一条弧；喙一个三角。超过这个数量就会在桌面图标上糊掉。
3. **辨识靠剪影，不靠颜色**
   去掉颜色后仍然是一只鸟。颜色只是加分，不是识别来源。

## 三、形象设定（定稿）

定稿由模型绘制，三个姿态存于 `docs/mascot/gugu-*.svg`。

```
         ╭─────╮
        ╱ ●   ● ╲        ← 圆头，微微向一侧倾斜
       │    ▾    │        ← 橙色喙
        ╲  ╭──╮ ╱
         ╲ │  │╱          ← 脖子收窄，再展开成饱满的胸腹
       ◟  ╰──╯  ◞        ← 尾羽从身后向两侧向上翘
          ▲  ▲            ← 带脚掌的橙色脚
```

**三个使它成立的特征**：

1. **头微微倾斜**——不是完全对称。这一点点倾斜是「活」和「呆」的分界。
2. **脖子有真正的收窄与转折**——头、颈、胸是三个不同的体积，而不是两个圆叠在一起。这是初版最大的问题。
3. **尾羽从身后向两侧向上翘**——既有鸟的辨识度，又形成向上的动势。

**眼睛**：竖椭圆，宽 2.45、高 3.35（64 网格），左上方一个 0.91 半径的白色高光，透明度 0.85。两眼的垂直位置略有错开（17.9 与 17.25），配合头部的倾斜。

**喙**：橙色，用曲线勾勒出鸽喙特有的圆钝感，不是尖三角。

**脚**：两条短橙线加一个小脚掌，有重量感。

**三个姿态**：

| 文件 | 姿态 | 用途 |
|---|---|---|
| `gugu-front.svg` | 正面站立，平静友善 | 主形象，用于页面角落、空状态 |
| `gugu-happy.svg` | 眼睛弯成笑眼 `^ ^`，翅膀张开上扬 | 练习完成、答对、庆祝 |
| `gugu-profile.svg` | 侧脸，只露一只眼 | **App 图标**，48px 下最清晰 |

## 四、配色

| 部位 | 颜色 | 说明 |
|---|---|---|
| 身体主色 | `#8AA4C8` 雾蓝灰 | 鸽子的真实羽色，且与译键主色系（蓝 #1CB0F6）同族但更沉，不与 UI 抢视觉 |
| 身体暗部 | `#6B84A6` | 只用于下腹一小片，制造一点体积感 |
| 翅膀 | `#9DB5D4` | 比身体亮一档，靠明度区分而不是描边 |
| 喙与脚 | `#FF9600` | 全身唯一暖色，视线焦点 |
| 眼睛 | `#1C2B43` | 与图标描边同色 |
| 信纸 | `#FFFFFF` + `#58CC02` 字 | 与成功色一致 |

**为什么不用纯灰**：纯灰的鸽子会和界面里的禁用态、次级文字混在一起。雾蓝灰既能被读作鸽子，又能和品牌色系共处。

## 五、主图标方案

桌面图标改为**信鸽侧脸**，取代当前的键帽：

- 背景：饱和绿 `#58CC02`（保持现有品牌色与 UI 一致）
- 主体：信鸽侧脸剪影，白色
- 唯一细节：橙色喙
- 尺寸：鸽头占安全区的 60%，下方留白

**为什么换掉键帽**：键帽是「这是什么产品」（一个键盘），信鸽是「这为你做什么」（帮你在两个语言之间传话）。后者更像一个可以记住的形象，也更像多邻国有 Duo 而不只是一个键盘图标。

侧脸比正脸更适合图标：正脸在 48dp 下两只眼睛会挤成两个点，侧脸只有一个眼睛加一个喙，轮廓更利落。

## 六、表情与动作

吉祥物成立与否，取决于它能不能「演」。先定四个基础状态：

| 状态 | 造型变化 | 用在哪 |
|---|---|---|
| **平常** | 站立，翅膀收拢 | 图标、页面角落 |
| **开心** | 翅膀张开上扬，眼睛变成两道弧 `^ ^` | 答对、完成练习 |
| **惊讶** | 头顶竖起一小撮羽毛，眼睛放大 | 连对新纪录、升级 |
| **鼓励** | 头微歪，一只翅膀抬起 | 答错时（不指责，只是「再来一次」） |

**动作**：只有三种，够用且不做过度设计
- 呼吸：整体上下浮动 2%，2 秒一轮
- 反应：出现时从 0.6 弹到 1.05 再回 1，约 400ms 的弹簧
- 开心时：翅膀以根部为轴旋转 ±12°，快速三下

## 七、在庆祝页上的用法

现在庆祝页只有一个静态奖杯。改成：

```
        ╭───────────╮
        │   咕咕    │   ← 信鸽从下方弹入，落在奖杯旁边
        │  🏆       │
        ╰───────────╯
         练习完成！
         12 / 15 记得
```

- 信鸽先弹出（400ms 弹簧），再开始呼吸循环
- 彩带从信鸽和奖杯之间的位置向上喷
- 若本次全对，信鸽切到「惊讶」+ 张开翅膀
- 若正确率低于 60%，信鸽切到「鼓励」，文案改为「这次有点难，再来一次会更好」

## 八、实现顺序

1. **矢量稿**：先在 24 / 48 / 128 / 512 四个尺寸画出静态信鸽，验证 48dp 下的辨识度 —— 这是唯一不能妥协的指标
2. **接入庆祝页**：静态版替换奖杯，加呼吸与弹入
3. **接入应用图标**：侧脸版替换键帽
4. **表情状态**：只在庆祝页按结果切换，先做开心与鼓励两种

## 九、明确不做的

- 不做 3D、不做拟真羽毛、不做渐变高光
- 不做动画逐帧图（用 Compose 变换即可，省体积）
- 不给它配语音
- 不在键盘界面里出现（键盘空间寸土寸金，吉祥物在那里只会碍事）

## 十、迭代记录

形象不是在纸上定下的，是渲染出来一版一版改出来的：

| 版本 | 问题 | 修正 |
|---|---|---|
| v1（手绘） | 头身连成一个椭圆，整体是一团，48dp 下只是几个模糊的点 | — |
| v2（手绘） | 分出了头和尾羽，但尾羽在正下方，与橙色脚混在一起读成四条腿 | 尾羽改到两侧偏后 |
| v3（手绘） | 底部分界仍然生硬，眼睛是两个无神的纯圆点 | 加颈部过渡片 |
| v4（手绘） | 可用，但对称、笔直，显得呆板 | 眼睛改竖椭圆 + 高光 |
| **v5（模型绘制）** | **定稿** | 头微倾、颈有转折、尾羽上翘、脚有脚掌 |

**为什么最终交给模型画**：我把设计约束写成了提示词（`prompt-for-chatgpt.md`），因为约束本身是清晰的，缺的是手的功夫——曲线怎么走、倾斜多少、尾巴怎么翘。手绘版在结构和配色上都对，但每一根曲线都是「差不多」；模型版在同样的结构里给出了更松弛、更有生命的线条。

**教训（两条）**：

1. **判断图标和吉祥物不能看大图。** 每一版都必须渲染到 48px 再看——v1 在 512px 下看起来尚可，在 48px 下完全失效，而 48px 才是它日常被看到的大小。
2. **约束写得越死，外部生成越可用。** 提示词里钉死了 viewBox、六个 hex 值、禁用的滤镜列表、「必须有头身分界和外翘尾羽」这两条硬要求，所以模型交回来的东西不需要返工就能进设计系统。
